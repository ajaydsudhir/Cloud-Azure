# Day 28: Troubleshooting Public Virtual Network Configurations

## Task
The Nautilus DevOps Team attempted to deploy an Nginx server on an Azure VM in a public VNet named `devops-vnet`, but they were unable to complete the setup successfully, and the server remains inaccessible from the internet.

As a DevOps team member, complete the following tasks:
1. **Verify VNet Configuration:** Ensure `devops-vnet` allows internet access.
2. **Attach Public IP:** A public IP named `devops-pip` already exists. Attach this public IP to the VM `devops-vm` to make it accessible from the internet.
3. **Ensure Accessibility:** Confirm the VM `devops-vm` is accessible on port 80.
4. **Install and Configure Nginx:** Install Nginx on `devops-vm` and ensure the service is enabled and running, listening on port 80.

- Ensure the Network Security Group (NSG) is attached to the VM's NIC or subnet and configured to allow HTTP traffic on port 80.

## Solution
1. Login to the Azure portal using the provided credentials.
2. Navigate to "Route Tables" and delete the route table associated with `devops-vnet` which is named "Block-Internet".
3. Add a new route to the route table with the following details:
   - **Route Name:** `Allow-Internet`
   - **Destination Type:** `IP Address`
   - **Destination IP Address/CIDR:** `0.0.0.0/0`
   - **Next Hop Type:** `Internet`
4. Navigate to "Public IP addresses" and attach the existing public IP `devops-pip` to the VM `devops-vm`.
5. Navigate to the "Network Settings" of the `devops-vm` create a inbound port rule to allow inbound traffic on port 80 named `Allow-HTTP`.
6. SSH into the VM `devops-vm` and install Nginx using the following commands:
```bash
ssh azureuser@<devops-vm-public-ip>
sudo apt update
sudo apt install net-tools -y
sudo apt install nginx -y
sudo systemctl status nginx
```
7. Run the following commands to verify that Nginx is listening on port 80 and accessible from the internet:
```bash
netstat -atnlp
curl <devops-vm-public-ip>
```
